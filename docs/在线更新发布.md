# 在线更新与本机发布

首个支持版本是 1.1.3（versionCode 113）。旧版须先手动覆盖安装一次，之后可在设置中点击“检查更新”。1.1.7 起每次启动首页就绪后自动检查一次并直接提示；失败时不干扰使用。

## 本机准备

保持原有 JDK 11、Android SDK 和 Python 构建环境。将当前 `C:/Users/zch/.android/debug.keystore` 复制到被 Git 忽略的 `.signing/current.keystore`，另保留备份；不要重新生成密钥。当前环境已经配置。

本地 `release-signing.properties`（被 Git 忽略）包含 `storeFile`、`storePassword`、`keyAlias`、`keyPassword`。路径相对仓库根目录。发布任务将验证证书 SHA-256 必须是 `195cc65bd18f8e04184423ad84306a9ed9582f4f0be5cf7d26b19371e4bcba62`，缺失或不符就停止。release 构建沿用原证书，关闭应用调试功能；签名文件和凭据不得提交。

## 预览与发布

在仓库根目录执行（PowerShell 7，确保中文路径和说明按 UTF-8 读取）：

```powershell
./tools/publish-release.ps1 -NotesFile docs/releases/1.1.3.md -PrepareOnly
```

此命令只在本地构建，生成 `dist/v1.1.3/Z.apk`、`update.json`、`SHA256SUMS.txt`，允许工作区有尚未提交的代码。核对 APK 版本、证书和说明后进行实机覆盖升级测试。

发布时，先提交并推送本次发布的代码，确保工作区干净且 HEAD 与 origin/main 一致。在本机为 `GITHUB_TOKEN` 环境变量配置仅限该仓库 Contents 读写权限的凭据，然后执行：

```powershell
./tools/publish-release.ps1 -NotesFile docs/releases/1.1.3.md
```

脚本直接连接 GitHub API，不通过公共代理发送凭据。它先建立草稿，上传并核对三个附件的 GitHub SHA-256 和大小，最后发布并设为 Latest。上传中断时保留草稿；检查草稿后手动删除不完整草稿再重试，已发布版本和已有标签不覆盖。旧的 `share` 发布页不变。

后续发布递增 `app/build.gradle` 的 versionCode，并同步修改 versionName、添加对应更新说明。脚本从实际 APK 读取版本与包名，版本号不能低于已有正式发布。代码推送不会自动触发发布。

## 协议与客户端行为

客户端从 `https://github.com/zongchenghuan0318/TVBox-fashion-UI/releases/latest/download/update.json` 读取六字段 JSON：`versionCode`（整数）、`versionName`、`changelog`、`apkUrl`、`sha256`、`size`（字节数）。APK URL 必须是该仓库与版本匹配的 `/releases/download/v版本/Z.apk`。Release 草稿不会成为 Latest。

元数据与 APK 按 gh-proxy.com、ghfast.top、GitHub 直连依次尝试，使用独立且验证证书和域名的 HTTPS 连接，不发送登录凭据。元数据每线路总超时 8 秒；下载连接超时 10 秒、读超时 20 秒。取消后不切线路，失败或取消清理临时文件；不支持断点续传或后台持续下载。

安装包大小、SHA-256、包名、版本和现有签名都通过验证后才调用系统安装器。Android 8 及以上按需开启安装授权；用户可拒绝安装。浏览器入口属于手动下载，应用无法替浏览器校验其下载文件。

## 验收

自动测试覆盖版本判断、无效更新信息、线路回退、HTML 响应、下载截断与校验失败、取消清理。真实电视仍需验证遥控器焦点和长说明滚动、授权返回、拒绝安装，以及从现有安装覆盖升级后直播源、收藏和历史保留。

公共加速服务的连通性和速度随网络变化，不承诺持续可用。初次正式发布前 Latest 尚无 update.json 时，手动检查将提示失败，自动检查保持安静。
